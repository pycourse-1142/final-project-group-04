##  一、專題規劃 (5/27 提交)
* **專題名稱**：捷運核心車站上下班尖峰時段人潮擁擠度與運量分流效率分析系統
* **資料來源**：臺灣政府資料開放平台 - 「臺北捷運各站分時進出量統計」(https://data.gov.tw/dataset/128506)
* **主要問題**：<br>
     1.讀取並解析特定月份數據中，各捷運車站在「早尖峰（07:00-09:00）」與「晚尖峰（17:00-19:00）」的每小時進出站人次。<br>
     2.經由核心運算進行分組與排序，找出「尖峰時段人流負荷最大」與「進出站人流最不平衡」的 Top 5 核心車站並進行排名。<br>
* **次要問題**：<br>1.原始數據中的進出車站名稱常帶有線別編號，如何透過字串處理或正規表示式精準剝離編號，以便與其他站點名冊進行對應分群與統計？<br>
               2.原始 CSV 檔案中若因跨月或系統異常出現空行、文字欄位錯亂，程式應如何設計防禦性邏輯，自動跳過或補值，確保執行時不崩潰。<br>
               3.確保「尖峰時段定義」與「Top 5 排序數量」設計為可隨時修改的變數參數。
* **預期產出圖表**：<br>1.早尖峰進站人數橫條圖： 核心車站早尖峰「進站人次」Top 5 排行。<br>
                   2.晚尖峰出站人數橫條圖： 核心車站晚尖峰「出站人次」Top 5 排行。<br>
                   3.每小時人流變化折線圖： 樞紐車站(多條路線交會，人流量大的車站) 24 小時進出站人潮的波動曲線。<br>
                   4.進出站平衡度散佈圖： X 軸為總進站數、Y 軸為總出站數，用以評估各車站的單向通勤特性。

### 2. AI 代碼失效紀錄與人工修正：

* **失效說明**：
    * **現象一（環境還原與遺失套件）**：執行主程式時終端機狂報 `ModuleNotFoundError: No module named 'pandas'`。經檢視發現，因學校電腦重開機自動還原，導致上週配置好的 `pandas`、`matplotlib` 等資料科學套件全數遺失。
    * **現象二（多環境錯位與執行失效）**：手動於終端機執行 `pip install` 後，點擊 VS Code 右上角播放鍵依然報錯。經人工觀察終端機路徑，發現電腦同時存在商店版 `Python 3.12` 與系統版 `Python 3.13`。`pip` 將套件裝到了 3.12 房間，但 VS Code 播放鍵卻預設呼叫 3.13 執行檔，導致代碼因環境錯位而持續失效。
    * **現象三（Git 忽略政策導致同步失敗）**：專案設定中的 `.gitignore` 包含 `results/` 過濾規則，導致圖片產出後無法透過標準 Git 流程推送，始終顯示 `Everything up-to-date`，不符作業評分要求。

* **人工修正方法**：
    * **方法一（精準路徑指引）**：放棄使用 VS Code 預設的不確定播放鍵，改由終端機手動輸入已完備套件之解譯器絕對路徑來強制點火執行：
        `& "C:/Users/TCUMI/AppData/Local/Microsoft/WindowsApps/python.exe" c:/Users/TCUMI/Desktop/final-project-group-04/main.py`
    * **方法二（Interpreter 環境校正）**：按下 `Ctrl + Shift + P` 呼叫 `Python: Select Interpreter` 功能，將 VS Code 全域核心手動切換至商店版 `Python 3.12`，一舉消除所有 `Pylance` 的遺失模組黃色警告線。
    * **方法三（Git 強制通行證）**：利用 `git add -f results/*.png` 強制繞過規則封鎖，順利將 4 張視覺化圖表強推上 GitHub 雲端倉庫，完美達成作業規範。

## 五、專題執行結果呈現 (佔比 15%)
> 請將產出的 4 張圖表存於 `results/`，並在此處進行分析簡述。

1. **圖表一 (名稱)**：早尖峰人流負荷 Top 5 核心車站
   * **分析簡述**：此圖表統計上午 7 點至 9 點間各車站的進出站總人次（進站 + 出站）。分析結果顯示，台北車站以顯著的總負荷量位居第一，其次為西門、市政府及忠孝復興等主要轉乘樞紐。此數據反映出台北捷運在早尖峰時段的核心通勤人流主要集中於板南線與交會轉乘站，可作為營運方在尖峰時段調度加班車或實施月台人流管制的重要指標。

2. **圖表二 (名稱)**：晚尖峰進出站最不平衡 Top 5 核心車站
   * **分析簡述**：此圖表計算下午 17 點至 19 點間各車站進站與出站人次的絕對差值（|進站 - 出站|）。數據顯示，台北車站與市政府站在晚尖峰時段呈現極高的不平衡度。市政府站因周邊為密集辦公區，晚尖峰出現極端的「進站人次遠大於出站人次」；而台北車站則因匯集轉乘與返鄉人潮，進出站落差顯著。此指標有助於評估各車站閘門的方向性調度（如增加進站或出站閘門數量）。

3. **圖表三 (名稱)**：台北車站 24 小時進出站人流變化折線圖
   * **分析簡述**：本圖追蹤特定樞紐車站（以台北車站為例）在全天 24 小時內的進站與出站人潮走勢。從折線圖中可以明顯觀察到傳統的「雙峰現象」：第一波高峰出現在上午 07:00 - 09:00（出站人次達到峰值，反映通勤上班潮），第二波高峰則出現在下午 17:00 - 19:00（進站人次大幅上升，反映下班與放學潮）。深夜與凌晨時段人流則趨近於零，完整勾勒出台北核心樞紐的日夜通勤脈動。

4. **圖表四 (名稱)**：全車站進出站平衡度散佈圖
   * **分析簡述**：本圖以橫軸代表總進站人次、縱軸代表總出站人次，並繪製一條 $Y=X$ 的對角基準線。圖中每一個散佈點代表一個捷運站，點距離基準線越近，代表該站進出站人流越平衡。分析發現，大多數郊區住宅型車站皆緊貼平衡線，而少數核心商業區車站（如市政府站）或交通樞紐（如台北車站）則顯著偏離基準線，呈現明顯的單向人流特徵，可用於區分「住宅型車站」與「工作型車站」的土地利用型態。
